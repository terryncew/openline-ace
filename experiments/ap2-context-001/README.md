# AP2-CONTEXT-001

External context-poisoning pressure test against unchanged OpenLine.

## Question

`malicious upstream context -> valid AP2 mandate -> native AP2 verification passes -> unchanged OpenLine receives it -> does the $80 execution cross?`

The external attack is AM1, **Authorization Beyond Stated Intent (T-23 -> T-1 -> T-4)**, from *Beyond the Mandate* (arXiv:2608.23858v1).

The frozen scenario follows the paper: the user asks for one camera with a $50 ceiling. Merchant-controlled catalog/tool context broadens the Open Payment Mandate to a $50-$80 amount range and leaves the payee unrestricted. The resulting mandate is then signed and verified with Google's native AP2 v0.2.0 SDK.

Only after native AP2 verification succeeds is the verified mandate adapted into the already-existing OpenLine receipt interface. No context-standing or provenance repair is added.

## Pinned substrate

- OpenLine ACE base: `78d4a2ef74436ea2c657bb64e978f79de81f173c`
- Google AP2 tag: `v0.2.0`
- Google AP2 commit: `b4587ac1d055888a73b4b21750973cffba961793`
- Paper: `arXiv:2608.23858v1`
- Companion artifact: `https://anonymous.4open.science/r/AP2_Beyond_the_Mandate`

The companion repository is cited for provenance but is deliberately not a CI dependency. Its anonymous 4open download endpoint can reject GitHub-hosted runners, so external artifact availability cannot decide this experiment. The AM1 transaction values are frozen from the public paper; native AP2 itself remains pinned and executed in CI.

## Interpret the result

- `VALID_AP2_POISONED_CONTEXT_BLOCKED_BY_UNCHANGED_OPENLINE`: strong external win, provided the block came from the pre-existing gate/evidence path.
- `VALID_AP2_POISONED_CONTEXT_CROSSES_UNCHANGED_OPENLINE`: useful negative. Final valid authorization is insufficient once poisoned context is already inside it; OpenLine would need upstream context/provenance standing or a narrower claim.
- `INDETERMINATE_OPENLINE_EVIDENCE_INCOMPLETE`: no promotion claim.

## Run

The GitHub workflow is the canonical run because it checks out Google's AP2 repository at the pinned commit and uses the native AP2 SDK.

```bash
python experiments/ap2-context-001/run_ap2_context_001.py \
  --ap2-root .external/AP2
```

`RESULT.json` is generated by the run and uploaded as a workflow artifact. It is intentionally absent from the source tree before execution.
